# 📘 Closed_Stack_Downloader v1.0.2 取扱説明書

## 🔐 はじめに：プライバシーと透明性

Closed_Stack_Downloader v1.0.2 は、**動作に不要な外部通信や情報収集を行う機能を実装していません。**

- 🚫 テレメトリ・トラッキング・広告なし
- 🚫 個人情報収集なし
- 🔑 パスワード / Cookie / 認証トークンの保存・送信なし
- 🧾 Refererはユーザーが使用を選んだ場合のみ送信
- 💾 設定はローカルTOMLへ保存
- 🔍 ソースコードを公開し、第三者による確認が可能

---

## 🎯 このツールについて

Referer対応・レジューム転送・Checksum検証を備えた、Closed Stack特化型の汎用一括ダウンローダーです。

1行1URLのTXTを読み込み、複数ファイルを順次または並列でダウンロードします。

## 🖥️ 動作環境

- Windows 11 x64
- .NET 10
- WinForms

配布用Self-contained EXEの場合、通常は別途.NET Runtimeをインストールする必要はありません。

---

## 📄 1. URLリストを準備する

UTF-8またはUTF-8 BOM付きのTXTを作ります。

```text
https://example.com/files/file01.mkv
https://example.com/files/file02.mkv
https://example.com/files/file03.zip
```

### ✅ URLリストのルール

- 1行1URL
- `http://` / `https://` の絶対URL
- 空行は無視
- `#` で始まる行はコメント
- `;` で始まる行はコメント
- Fragment（`#...`）は通信対象から除外
- Query Stringは保持
- 重複URLは除外

### 🖱️ 読み込み方法

- 「URLリスト」の参照ボタン
- またはTXTを入力欄へDrag & Drop

---

## ✅ 2. Checksumファイルを指定する

対応形式：

- 📑 `.manifest`
- 🔐 `.sha512`
- ⚡ `.blake3`

「追加」ボタン、またはChecksum欄へのDrag & Dropで読み込めます。

複数のChecksumファイルを同時に利用できます。

### 🔎 検証の考え方

Checksum情報に含まれる項目をすべて満たす必要があります。

- Sizeあり → Size一致
- SHA-512あり → SHA-512一致
- BLAKE3あり → BLAKE3一致

SHA-512/BLAKE3が一致したファイルだけを「検証済み」とします。

### ⚠️ Checksumなし

「Checksum情報がないURLもダウンロードする」は初期状態でOFFです。

ONにした場合はダウンロードできますが、完了状態は：

**完了（未照合）**

となります。

Checksumなしのファイルを「検証済み」と表示することはありません。

## 🧾 4. Refererを設定する

### Refererが必要な場合

1. 「Refererを使用」を選択
2. HTTP(S)のReferer URLを入力
3. ダウンロードを開始

実際に使用したRefererは履歴へ記憶され、次回プルダウンから選択できます。

### Refererが不要な場合

「送信しない」を選択します。

この場合、Referer Headerは送信しません。

---

## ⚙️ 5. ダウンロード設定

### 🧩 同時Download数

範囲：1～6

初期値はアプリ設定に従います。回線やサーバー負荷に合わせて調整してください。

### 🔄 再試行回数

一時的な通信エラーなどで失敗した場合の再試行回数です。

`Retry = N` の場合：

- 初回1回
- + 最大N回の再試行

となります。

### ⏱️ タイムアウト

巨大ファイル全体の総時間制限ではありません。

主に接続・Response Header待ち・転送中の無通信状態に使用されます。

## ⏯️ 7. 一時停止・再開

### ⏸️ 一時停止

「一時停止」を押すと現在のHTTP通信を安全に停止します。

途中データは：

```text
filename.ext.part
filename.ext.part.meta
```

として保持されます。

### ▶️ 再開

「再開」を押すと、安全条件を確認してRange Resumeを試みます。

---

## 🛡️ 8. Resumeの安全性

本ツールは単純に古い `.part` へ続きを追記しません。

Resume時には以下を確認します。

- 🔗 保存済みFinalUrlと今回FinalUrl
- 🏷️ Strong ETag
- 📏 Content-Range開始位置
- 🔢 Total Length
- ✅ 利用可能なChecksum情報

Strong ETagが利用可能な場合は `If-Range` を送信します。

FinalUrlが変化している、Rangeが不正、Validatorが一致しないなど、安全性を確認できない場合：

**旧断片へ追記せず、先頭からFresh Download**

します。

### 🔁 Retry上限

1つの論理Attemptで：

- Resume Request：最大1回
- Fresh fallback：最大1回

FreshからさらにFreshを繰り返しません。

異常なServer Responseが続いても有限回で終了します。

## ✅ 9. 完了状態の見方

### 「検証済み」

SHA-512 / BLAKE3等、指定された完全性検証に成功しています。

### 「検証済み・既存」

保存先に既に存在したファイルがChecksum検証に成功したため、ネットワークアクセスせず利用しています。

### 「完了（未照合）」

Checksumなしでダウンロードしたファイルです。

### 「完了（サイズ確認のみ）」

Sizeのみを確認しています。暗号学的Hash検証済みではありません。

### 「Checksum不一致」

完全性検証に失敗しています。正式な完成ファイルとして確定しません。

### 「アクセス拒否」

HTTP 401 / 403等。

### 「リンク切れ」

HTTP 404 / 410等。

---

## ♻️ 10. 失敗のみ再試行

失敗した項目だけを再試行できます。

Checksum不一致など、古い断片の再利用が安全でない場合はFresh Downloadを行います。

## 💾 12. 設定保存

実行ファイルと同じディレクトリに：

`Closed_Stack_Downloader.toml`

を保存します。

主な保存対象：

- URLリストPath
- ChecksumファイルPath
- 保存先
- Referer履歴
- 同時Download数
- Retry
- Timeout
- Font Size
- Window位置・サイズ
- Grid列幅

ダウンロード結果や秘密情報は保存対象ではありません。

## 🌐 13. 通信仕様

- HTTP(S) GET

- `Accept-Encoding: identity`
- 最大10 Redirect

- HTTPS → HTTP downgrade拒否
- Cookie未使用
- Authorization未使用
- テレメトリ未実装

## ⚠️ 15. 注意事項

- 正当にアクセス権を持つURL・コンテンツに使用してください。
- Refererはアクセス制御を突破する機能ではありません。
- Serverが要求する正規のRefererをユーザーが指定するための機能です。
- Checksumなしのファイルは暗号学的に完全性を証明できません。可能な限りSHA-512またはBLAKE3を利用してください。
